# Registratura

Консольная электронная очередь поликлиники. Для запуска из папки проекта нужен .NET 10.

```powershell
dotnet run
dotnet run -- --compare
```

Вторая команда сравнивает последовательные запросы к учебному госреестру, ФОМС и архиву с параллельными. В контрольном запуске получилось **4,56 с** и **2,01 с**. Запросы получают один и тот же ПИН и могут выполняться независимо. `Task.WhenAll` завершается после всех трёх задач, поэтому при отказе госреестра на 1,5 секунде регистратор увидит ошибку после завершения архива около 2 секунд. Регистрация при отказе отклоняется, как и в MedicalApi.

## Сценарии для показа

| Ввод | Результат |
| --- | --- |
| Команда 2 при пустой очереди | Понятное сообщение, меню остаётся доступным |
| Команда 4, затем `abc` или слишком большое число | Программа просит ввести номер цифрами |
| Команда 4, затем `15` при отсутствии талона | Сообщение, что талона нет |
| Команда 1, ПИН `21203199850123` | Айбек Асанов, полис есть, карта МК-50123 |
| Команда 1, ПИН `20101200000000` | Госреестр не отвечает, талон не создаётся |
| Добавить `12507200350456` и `20211198500789`, затем команда 7 | Оба отправляются в платную кассу |
| Поставить в очередь двоих, у второго оставить телефон пустым, затем команда 2 | Первый вызван, программа сообщает об ошибке SMS и продолжает работу |

Льготники идут перед обычной очередью в порядке регистрации. Дополнительная функция показывает время ожидания каждого пациента на табло.

## Что объяснить на защите

- `TryParse` подходит для ожидаемых ошибок ввода. Свои исключения сообщают о состоянии очереди из её методов. Общий `catch (Exception)` стоит последним, чтобы сначала обрабатывались конкретные типы исключений.
- Изменение списка внутри `foreach` приводит к `InvalidOperationException`. В прямом `for` после `RemoveAt(i)` следующий элемент сдвигается на текущий индекс, а `i++` его пропускает. В исправлении сначала собираются все пациенты без полиса, затем выполняется `RemoveAll`.
- У `async void` вызывающий код не получает задачу, из которой можно извлечь ошибку. `SendAsync` возвращает `Task`, поэтому `await` внутри `try` даёт обработать исключение.
- Если вызвать метод с `Task` без `await`, исключение останется в задаче, пока её результат никто не наблюдает. `Thread.Sleep` блокирует поток сразу, поэтому при такой замене вызовы выполняются по очереди ещё до `WhenAll`.
